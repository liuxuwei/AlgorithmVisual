# Proposal

## Why

当前应用只内置了 4 个算法（冒泡/快排/DFS/BFS），内容固定、覆盖面窄，与 "LeetCode 高频算法可视化" 的产品定位不符。用户希望把内置算法方案改为从网络获取 LeetCode 热题 100，并为每道题提供对应可视化。

网络接口实测表明，LeetCode 官方「热题 100」可直接获取且正好 100 题、分 17 个专题组，因此具备落地条件。但网络只能提供题面等**内容**，可视化步骤与代码行号必须由本地实现，这决定了本次变更的核心工作是"题库接入 + 100 道题的本地步骤脚本"。

## What Changes

- 新增网络题库能力：通过 LeetCode 网页端 GraphQL 拉取热题 100 的题号、标题、难度、专题分组与中文题面；提供本地缓存与内置兜底快照，Web 端与断网场景自动降级到快照。
- 新增题目目录模型：以 `titleSlug` 作为稳定标识，替代当前基于中文 `name` 的查找方式，承载题目元数据、分组、难度、题面与可视化描述符。
- **BREAKING** 注册机制调整：可视化器从"按分类注册算法"扩展为"题目目录 + 题型渲染器 + 每题步骤脚本"三层结构；现有 `AlgorithmVisualizer` 接口保持不变，但其注册与查询入口改为目录驱动。
- 新增 14 种题型渲染器与 100 份每题步骤脚本：覆盖普通数组、双指针、滑动窗口、前缀和、二分查找、哈希表、矩阵/网格、链表、二叉树、回溯、栈、堆、一维动态规划、二维动态规划。
- 扩展可视化数据模型：`Element` 新增链表节点、矩阵格子、栈帧、哈希桶等类型；`Action` 新增指针移动与区间标注；`InputSchema` 新增字符串、矩阵、多字段输入，UI 同步支持。
- **BREAKING** 首页改为热题 100 为主入口（17 个专题组 + 难度筛选），现有 4 个算法保留为「基础算法」二级入口。
- 可视化播放页新增折叠式题面卡片，保留原有"可视化 + 代码 + 播放控制"三区与代码逐行高亮。
- 代码与演示输入改为随题目描述符本地维护，移除页面内按中文名硬编码预置用例与源码的做法。

## Capabilities

### New Capabilities

- `problem-catalog`: 网络题库获取、题目目录模型、本地缓存与内置兜底快照、断网与 Web 降级行为。

### Modified Capabilities

- `algorithm-library`: 注册与查找机制从中文算法名改为题目目录驱动，新增题型渲染器与每题步骤脚本的注册约定，保留算法层与渲染层隔离约束。
- `visualization-framework`: 扩展 Element、Action、InputSchema 以支持链表、矩阵、栈、哈希等新题型所需的可视化表达。
- `flutter-ui`: 首页改为热题 100 主入口并保留基础算法入口，播放页新增折叠题面卡片，输入面板改为由题目描述符提供。

## Impact

- 代码：
  - `lib/algorithms/`：新增题型渲染器与 100 份步骤脚本，调整 `registry.dart` 注册入口。
  - `lib/core/scene/`：扩展 `element.dart`、`action.dart`、`input_schema.dart`。
  - `lib/core/visualization/`：新增链表、矩阵、栈、哈希等渲染组件并接入 `scene_renderer.dart`。
  - `lib/ui/`：重写 `home_page.dart`、新增题目列表页，改造 `visualization_page.dart` 与 `algorithm_list_page.dart`。
  - `lib/main.dart`：启动流程接入题库加载与降级。
- 依赖：新增 HTTP 客户端依赖；题面为 HTML，需要 HTML 渲染方案（依赖选型在 design 中确定）。
- 资源：新增兜底题库快照（约 200-300KB）与开发期抓取脚本产出。
- 测试：现有 `test/` 下用例需随注册机制调整；新增题库解析、缓存降级、步骤脚本帧生成的测试。
- 外部系统：依赖 LeetCode 网页端非公开 GraphQL 接口，无稳定性承诺，因此兜底快照为必需项而非可选项。
